     Markdown-Based Project Knowledge System for QA AI Agents

     Context

     The current QA AI Agents system works well but lacks project-specific
     knowledge. When placed in any repository, the agents can only perform
     generic testing without understanding the business domain, critical flows,
     or project structure. This plan implements a markdown-based knowledge 
     system with smart automatic discovery.

     Problem Statement

     - Agents treat all projects identically with only basic stack detection
     - No understanding of business entities, critical flows, or domain rules
     - Tests are generic rather than context-aware
     - No persistent knowledge repository for project-specific context

     Solution Overview

     Implement a markdown-based knowledge system with automatic discovery where:
     1. Agents automatically scan repositories to understand project structure
     and flows
     2. Discovered knowledge is stored in markdown files in .qa-knowledge/
     directory
     3. Agents reference this context when executing testing commands
     4. Smart detection ensures knowledge stays current (auto-refresh if >7 days
      old)

     ---
     Implementation Plan

     Phase 1: Knowledge Base Structure (Week 1)

     1.1 Create Markdown Knowledge Templates

     Directory: .qa-knowledge/ (NEW)
     Create markdown templates for storing discovered project knowledge:

     - project-overview.md - Tech stack, frameworks, project structure
     - critical-flows.md - User journeys, business processes, key interactions
     - api-endpoints.md - API routes, authentication, data models
     - database-schema.md - Database models, relationships, constraints
     - testing-config.md - Test users, environment variables, fixtures

     1.2 Build Enhanced Project Discoverer Agent

     File: agents/project-discoverer.md (ENHANCED)
     - Comprehensive codebase analysis
     - Extract tech stack, critical flows, API endpoints, database schema
     - Generate structured markdown files in .qa-knowledge/
     - Support framework-specific discovery (React, Vue, Next.js, FastAPI,
     Django)
     - Smart timestamp tracking for auto-refresh

     1.3 Add Context Loading to All Agents

     Files: All 8 existing agent .md files
     - Add "Knowledge Base Check" section at start of each agent
     - Implement smart detection: check if .qa-knowledge/ exists and is current
     (>7 days)
     - Auto-trigger discovery if knowledge missing or outdated
     - Load and reference markdown context during testing

     ---
     Phase 2: Context-Aware Agent Enhancement (Week 2-3)

     2.1 Update UI Flow Tester

     File: agents/ui-flow-tester.md
     - Read critical-flows.md for intelligent test generation
     - Use project-overview.md for framework-specific test patterns
     - Reference testing-config.md for user credentials and environment setup
     - Generate tests based on discovered routes and components

     2.2 Update API Contract Tester

     File: agents/api-contract-tester.md
     - Use api-endpoints.md for comprehensive endpoint coverage
     - Reference database-schema.md for data validation
     - Test authentication flows from critical-flows.md
     - Validate API contracts against discovered schemas

     2.3 Update DB Integrity Checker

     File: agents/db-integrity-checker.md
     - Use database-schema.md for schema validation
     - Test relationships and constraints from discovered models
     - Validate referential integrity based on discovered foreign keys
     - Check cascade rules from discovered ORM configurations

     2.4 Update E2E Orchestrator

     File: agents/e2e-orchestrator.md
     - Check knowledge base status before orchestrating tests
     - Trigger discovery if needed
     - Pass context references to all specialist agents
     - Coordinate tests based on discovered critical flows

     ---
     Phase 3: Advanced Context Integration (Week 4)

     3.1 Update Performance Load Tester

     File: agents/perf-load-tester.md
     - Use critical-flows.md for realistic load scenarios
     - Target key endpoints from api-endpoints.md
     - Set performance baselines based on discovered tech stack

     3.2 Update Security Scanner

     File: agents/security-scanner.md
     - Use api-endpoints.md for targeted security testing
     - Scan authentication flows from critical-flows.md
     - Check for sensitive data patterns from database-schema.md

     3.3 Update Accessibility Auditor

     File: agents/a11y-auditor.md
     - Use critical-flows.md to prioritize key user journeys
     - Test critical pages from discovered routes
     - Validate framework-specific accessibility patterns

     3.4 Update Test Reporter

     File: agents/test-reporter.md
     - Include project context from project-overview.md in reports
     - Reference specific flows and endpoints tested
     - Link findings to discovered project structure

     class Product(Base):

     - When User is deleted: Delete associated Order and Cart records
     - When Product is deleted: Delete associated CartItem records
     - When Category is deleted: Set Products.category_id to NULL

     ## Key Design Decisions

     ### 1. Markdown-Based Knowledge Storage
     **Why**:
     - Human-readable and easy to edit manually
     - Works with existing markdown editors and Git
     - No special parsing tools required
     - Can be version controlled alongside code

     ### 2. Smart Auto-Discovery with Caching
     **Why**:
     - Automatic discovery provides immediate value (zero configuration)
     - Smart caching prevents expensive re-scanning (7-day freshness)
     - Detects major changes for timely updates
     - Manual override available when needed

     ### 3. `.qa-knowledge/` Directory Structure
     **Why**:
     - Keeps QA knowledge organized and separate from source code
     - Easy to locate and manage
     - Simple to include/exclude from version control
     - Clear purpose with dedicated directory name

     ### 4. Context-Driven Testing
     **Why**:
     - Tests become project-aware automatically
     - More relevant test scenarios based on actual flows
     - Reduced maintenance burden (context drives test generation)
     - Better bug detection in business logic

     ### 5. Framework-Specific Discovery
     **Why**:
     - Different frameworks have different patterns (React vs Vue vs Next.js)
     - Tailored discovery produces more accurate knowledge
     - Extensible to support new frameworks easily
     - Better test generation based on framework conventions
